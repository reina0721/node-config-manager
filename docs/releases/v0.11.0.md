# nodectl v0.11.0

- 新部署默认使用 `https://auth.<根域名>/` 作为私有认证地址。认证请求通过设备代理抵达网关，认证域名不进入公网解析清单。完整客户端配置优先把认证请求交给同一设备的 nodectl 入口。
- 控制台可安装到测速域的 `/nc/`，浏览器和节点配对使用 HTTPS 443。首次切换经 SSH 执行，原控制台监听在新入口检查通过后停止。
- 共享客户端拥有独立 UUID，包含六个默认配置项以及管理员选定的附加入站和外部分享链接。每个账号的设备继续持有独立凭据。

## 从 v0.10.1 迁移

先备份 nodectl 当前及上一份快照、账号状态、控制台静态文件和服务状态。用 `install.sh --version v0.11.0 --install-only --execute` 安装签名程序，并验证旧快照。

使用受保护的 Cloudflare 凭据签发或导入独立认证证书。签发只使用认证域名下的临时 ACME TXT。

```sh
nodectl issue-auth-certificate --hostname auth-test1.materiallib.com \
  --token-file /etc/dmit-node/credentials/cloudflare-token
nodectl deploy --non-interactive --manual-certificates --skip-dependencies \
  --domain-suffix materiallib.com --auth-prefix auth-test1 --shared-console true
```

审阅预览后，以相同参数附加 `--execute --approve <计划摘要>` 应用。使用已验签的安装器安装与程序匹配的控制台。

```sh
bash install.sh --version v0.11.0 --switch-admin --admin-port 443 --execute
```

用 `https://<测速域名>/nc/` 登录并确认管理和原服务可访问。中断时先用 `nodectl admin recover-shared` 恢复控制台事务，再按节点的事务状态决定是否恢复配置。
